# foxtrot-labor-pulse

**Owner:** Samuel Kosco — Data Analyst, Foxtrot Aviation Services
**Purpose:** Read-only Labor Pulse dashboard for ops — the web replacement for opening `Live Commercial Pulse Sheet.xlsx`. Budgeted vs worked labor hours per station per day, with weekly averages and variance.

The page is intentionally uneditable: ops get a link, not the workbook. The repo name carries a random suffix and the page carries `noindex` because the Pages site is public — treat the URL as the access control and share it only internally. Since the org migration the CODE is private (org repo); only the rendered site is public. The platform embeds this site and its JSON feeds the platform homepage stats.

## How it works

1. `.github/workflows/refresh.yml` is poll-triggered (2026-08-21; dispatcher-fired since 2026-08-31 — GitHub's cron is fully retired org-wide): the Foxtrot Platform's dispatcher fires a `workflow_dispatch` every 30 min, 6:00 AM–6:30 PM Eastern (manifest `Monitoring/schedules.json`). Each fire is a light poll — `check_sources.py` compares each source's Graph lastModifiedDateTime against `sources_meta.json` (committed at every build) and a full rebuild runs only when something changed — so the main refresh follows the ~6 AM Eastern Paylocity relay within minutes and same-day debrief edits surface within the poll interval. Tick the `force` input (the Actions-tab default for humans) to rebuild unconditionally. The workflow name ("Daily Pulse Refresh") is load-bearing — mirror.yml's workflow_run matches on it.
2. `fetch_sources.py` downloads the 13 source files from the Data Hub SharePoint drive via Microsoft Graph (client credentials — same Foxtrot Report Automation app and drive ID as the compliance trackers). Beyond the original pulse-workbook sources this includes `AA Debriefs.csv` (STL/PVD AA cabin jobs: Job Type DTC/RSTC→AA Turn, RON/RRON→AA RON, Security→AA Security, Ultra→Ultra, Shroud→Shroud Cleaning; Status=Completed only) and `APU Wash.xlsx` Sheet2 (JFK/MCO). **APU Wash Sheet2 dropped its Status column in Aug 2026** in favour of one numeric column per service — `APU Wash`, `Landing Gear Bay Wash`, `Partial Belly Wash` — valued 1 (completed), 0.5 (cancelled, half billable) or 0 (no job). Only a 1 counts toward the pulse; `load_apu` raises if any of the three columns goes missing rather than silently counting zero.
3. `build_pulse.py` reproduces the workbook's full calculation chain from those sources (the workbook itself is never read) and renders `index.html` from `template.html` with the data embedded.
4. The workflow commits `index.html` + `pulse_data.json`; GitHub Pages serves it.

## Calculation notes

- **Worked Hours** = hourly punched hours + 40/7 h per active salaried employee in the station's labor dist ("Not Defined" labor dist repaired from the employee master). Directors/Regional Managers are excluded, matching the workbook query. (Exactly: the titles Director, Regional Director, Regional Manager II and — since 2026-10-21 — Head of Internal Operations; `EXCLUDED_TITLES`. RM Is are counted.)
- **A salaried manager over several pages is SPLIT across them, from 2026-10-01** (Sam, 2026-10-21; `salary_split`, `SPLIT_START`). Before that date nothing changed. From it, on each day, an active salaried person whose org-chart purview that day reaches 2+ pages (through those pages' salaried dists) has their 40/7 h shared across those pages instead of landing on their home dist — in proportion to each page's **average daily budget over the 30 days BEFORE that day** (`SPLIT_WINDOW_DAYS`), or over the days since the page went live when that is more recent (an MRO board from its first SCHEDULED job, not a plane's induction; a gated page from its first debrief). A page not live yet weighs 0, so IAD takes nothing until it launches. Each day uses only earlier budgets, so a later budget change never reaches back. A day on which every one of the person's pages weighs 0 is not split (they count at home as before). **The purview comes from the platform**, which owns the org chart: `Definitive Lists/Salaried Purview.csv` (engine/purview.py there, hourly, written on change) is a DATED history — `From`/`To` per row, seeded `From` 2026-10-01, a change closes the old row the day before and opens a new one — so an org-chart change only reaches dates after it. Every month's budgets are computed BEFORE any worked hours (`month_budgets` / `station_budget`, split out of `build_month`) because the weights cross month boundaries. Each station carries `salary_split` (shared hours per day, already inside `worked`; the day tooltip shows it as "Shared managers"), the payload's top-level `salary_split` lists who is split with today's h/week per page, and `salary_split.json` (gitignored) hands the same split to build_mro_hours.py, which refuses to run without it so the MRO calendar can never disagree with the page. Verified at launch: April–September identical to before, October conserving the company total (+1.6 h of rounding), MRO feed equal to the page on every day.
- **Day attribution differs by station type.** Commercial stations use the workbook's rule — punch-in minus 12 h, so an overnight shift credits the day it started. **Facility stations use the plain calendar day of the punch** (owner decision, Aug 2026): they don't run overnight shifts, and the 12 h shift-back was pushing normal morning starts (TUS FAC begins 5–6 AM) onto the previous day. A station counts as facility when its sheet name ends in "FAC" or all its services are flat daily budgets (`facility` flag, set in `merge_budget_config`). Note `IAH` draws on both `IAH CABIN` and `IAH FAC` but is a commercial sheet, so all its hours keep the shift-back. **The rule is published per station**: `attribution_of()` states in words what `worked_hours()` does, and each station carries `attribution` plus `labor_keys` / `salary_keys` in `pulse_data.json` (Sam, 2026-10-19), so the platform's Manage Pulse Locations page renders the real rule instead of a typed copy — the copy it replaced had drifted to 26 rows agreeing with the live 45 locations on 6. Where every one of a station's dists is in `plain_day_dists`, it says plain calendar day rather than naming the shift-back and then excepting all of it.
- **Holiday/PTO pay is excluded** (rows with a punch-in, no punch-out, and paid hours > 0 — owner decision Aug 2026; the Excel workbook still counts these).
- **AA gaps are shown, not filled.** AA's feed runs through AA's internal system and whole days go absent. Those days now count only what arrived (`aa_missing_days` finds them) and carry an asterisk, rather than the old 7-day average.
- The page force-reloads itself every 30 minutes so an open tab can't show stale data.
- **Nothing is estimated (Sam, 2026-09-08).** A punch still open when `This Years Hours.csv` was cut carries 0 paid hours and is simply excluded; the day is marked with an asterisk saying how many shifts are outstanding, and the figure rises on its own once they close. `incomplete_n` counts them (punch-in within the 18 h before the file was generated, so abandoned and future-dated placeholder punches don't qualify).
- **Budgeted Hours** = per-service aircraft counts (from the airline debrief workbooks, Yes→1 flag logic identical to the Power Queries) × the station's hours-per-job rates, plus flat daily facility budgets released only for elapsed days.
- Weekly averages cover elapsed days only; variance = |1 − worked/budgeted| rounded like the sheet.
- **Closeout Compare drives two corrections and the asterisks.**
  `Power Flows/Debriefs/Closeout Compare.xlsx` reconciles each night's closeout
  against the debriefs. The pulse acts on exactly two `Discrepancy` values,
  matched as canonical labels only: **Double Debrief** (the job was counted
  twice - `apply_double_debriefs` drops one duplicate row, matched on
  table+date+tail, and only when two or more really are present) and **Missing
  from Debrief** (on the closeout with no debrief - deliberately NOT invented,
  so the count stays understated and says so). Both raise an asterisk. A row
  whose **Status is Closed** (any case) is settled: the debrief becomes
  authoritative, so it neither corrects a count nor raises an asterisk. Every
  other discrepancy type in that sheet (service mismatches, typos,
  missing-from-closeout) is paperwork and is ignored; the free-text variants of
  double/missing are ignored too rather than fuzzily parsed, since a wrong match
  would silently move a station's numbers.
- **A service can start mid-window.** `starts: "YYYY-MM-DD"` on a service in
  `station_overrides.json` means it contributes nothing before that date rather
  than being back-applied over history (`service_start`; CVG's Envoy Facility
  begins 2026-09-14). It applies to counted and fixed services alike. Note a
  fixed budget still only releases on ELAPSED days, so a future start shows all
  zeros until the date arrives - that is not a misconfiguration.
- **A week with no variance says WHY.** `variance` is null for two unrelated reasons and the page used to print "no days elapsed" for both: a week genuinely in the future (`avg_budgeted` null, no day elapsed yet) and a week that has been and gone with nothing budgeted (`avg_budgeted` 0). The second is what a Private/MRO location shows when its board was never filled in for that week, and labelling it "no days elapsed" told the reader a past week had not happened (Sam, 2026-10-23, RFD MRO week 2 — 26.7 h worked on the Thursday). Now: "no days elapsed" only when none have, "no budget scheduled" when the week elapsed with labor and no budget, "no activity" when neither side has anything.
- **The "Misc." row is hand-logged work** (Sam, 2026-10-27; named `Other` for half a day, renamed so this page and the Private/MRO board use the same word). `Pulse Sheets/Misc Work.json` — written by the platform's Add Misc Work form, one entry per job with a date range and the revenue it earned — becomes an extra service row on that location's page: the revenue spread EVENLY over the days the job ran (the form asks for a range, not a per-day split) and divided by `MISC_RATE` for the hours. Days land where they are DATED — misc work is a record of work, not a forward allowance, so unlike the flat facility lines it is not gated on the day having elapsed (Sam, 2026-10-27: work logged for today through two days out produced no row at all). The month total still sums only elapsed days, so nothing is inflated, and the Private/MRO board draws the same entries on the same days. The row is added BEFORE the launch gate so a location that is not being scored yet does not start carrying budget because someone logged a job against it. **The rate is a flat $44 at every location and is shown NOWHERE on the page** (Sam's instruction): per-location goal rates ARE derivable — invoiced revenue over budgeted hours holds to within 7% for most locations — but they range from $29 (DCA CABIN) to $87 (MCO CABIN), so publishing one number would be wrong for most of them. The row is excluded from the rates card and from `allPriced`/`byRate` for the same reason, so logging one job at FLL cannot flip its card out of the collapsed "all labor at one rate" form. Each entry carries a NAME (required — it is what a board block and this row's tooltip lead with) and an optional DESCRIPTION (the detail you only see on opening it). Hovering a cell shows the name, the description and the revenue, never the rate. The row does not expand: the tooltip is the detail.
- **Asterisks, not tildes.** `worked_notes` / `budget_notes` are
  `{day: sentence}` maps rendered as `*` with a tooltip. The tilde estimate
  marker is gone.
- **`Pulse Sheets/Service Budgets.xlsx` is the owner-editable control panel.** One sheet per location, columns Service | Budget. It decides which locations the pulse shows, which services each has, and the hours-per-job rates — edits flow into the page at the next refresh. Adding a sheet adds a location: the airport code is the first 3 letters of the sheet name; the labor dist defaults to `<CODE> FAC` if the sheet name contains "FAC", else `<CODE> CABIN`; service rows are interpreted via `service_catalog.json` (recognized names like "Envoy IHC", "PSA RON", "GoJet CE", "Facility Budget" — matching is case/punctuation-insensitive). Unknown service names are treated as a flat daily budget of that many hours, with a build-log warning.
- **The workbook's `Locations` sheet says whose hours each location counts and how** (Sam, 2026-10-19) — columns `Sheet | Labor Dists | Attribution | Salaried Dists | Notes`, one row per location sheet, and it is the FIRST tab. Before it, those two facts lived in three places at once — the `<CODE> CABIN` / `<CODE> FAC` naming convention, `stations.json`, and `station_overrides.json` — none of them visible to whoever adds a sheet, so adding a location silently GUESSED both. The index beats all three, the FAC-name rule included, so a sheet that says `shift` gets shift. **Attribution** takes `shift` (12 h shift-back), `day` (plain calendar day), a window like `07:00-19:00` (CLE DAY / CLE NIGHT; a wrapping window is overnight), or per-dist `DIST=day; DIST=shift` for a pooled page whose crews differ. **Salaried Dists** is blank for "the same dists", `none` for a page that counts hourly punches only (CLE DAY), else its own list. A sheet the index doesn't name is a **hard failure**, as is an empty Labor Dists or Attribution cell — the error says what to type. **A workbook with no index sheet is now a hard failure too** — tolerated only during the rollout, fatal since `station_overrides.json` gave up its copy of these facts, because without the sheet the 12 pooled and split locations would quietly fall back to the `<CODE> CABIN` convention and read the wrong dists. Restore it from the workbook's version history; a stale page with a red workflow beats a confident wrong one. Migration was verified a no-op against the published `pulse_data.json` twice — once with the sheet added, once with the 95 lines of duplicated `labor_keys` / `salary_keys` / `plain_day_dists` / `shift_window` deleted from `station_overrides.json` (which now holds only service specs, groups and launch gates). Note `make_budget_workbook.py` rebuilds this workbook from `stations.json` and now refuses to run when it exists — it would destroy the renames, the index and the SharePoint customXml parts.
- **ADDING A NEW LABOR DIST TO THE PULSE? THE SHEET ASKS — fill in its `Locations` row** (Sam, 2026-09-28; made a build failure 2026-10-19 rather than a question to remember). Non-facility stations default to the 12-hour shift-back attribution (an overnight shift credits the day it started), which WRONGLY pushes a day crew's morning punches onto the previous day. A day-only crew either belongs to a facility station (plain attribution) or must be listed in its station's `plain_day_dists` in `station_overrides.json` — first case: `DFW WIDEBODY` (widebody team never works past midnight), which now sits on its own `DFW WIDE` page after one day pooled inside `DFW-DAL`; the flag moved with it, and DFW-DAL's CABIN + DAL PRIV keep shift-back. `plain_day_dists` is per-dist and flows through `worked_hours()`, so build_mro_hours.py honors it too.
- `stations.json` is the per-station spec config **auto-derived from the pulse workbook's formulas** by `extract_config.py` (local-only script). It still supplies the counting rules and labor-dist exceptions (TYS PSA, STL GOJET, IAH CABIN+FAC) for existing stations; `make_budget_workbook.py` regenerates Service Budgets.xlsx and `service_catalog.json` from it.
- **JSX stations** (`BUR-SNA`, `TEB-HPN`, `SCF PRIV`, `DAL PRIV`) read `Power Flows/Debriefs/JSX Debriefs.xlsx`, table `Debriefs` on Sheet1 — one row per tail with 0/1 columns for RON, Interior Detail, Exterior Detail and Carpet Extraction, keyed by `Service Location`. **Exterior details are priced by airframe** (Aug 2026): the build splits the single `Exterior Detail` flag into `Exterior Detail ATR` (Plane Type contains "ATR") and `Exterior Detail 145` (everything else, deliberately including the odd unreadable `#N/A` Plane Type - the build logs those rather than dropping them). Biohazard was retired as a service; the column still exists in the debrief but nothing reads it. Two sheets each cover two airports (Excel forbids `/` in sheet names, hence the hyphen); their specs list one COUNTIFS per airport and the build sums them. **Rows dated before `JSX_START` (2026-08-01) are ignored** — Foxtrot took the contract over on 8/1 and the earlier rows are the previous vendor's service history, backfilled to seed compliance windows (they all carry zero revenue). JSX stations therefore read zero for May–July on purpose. **`SNA PRIV` and `SCF PRIV` do not exist in Paylocity yet**, so BUR-SNA counts only BUR's labor and SCF reads 0 worked hours until those codes are created. JSX services are all `aircraft: false`, so those stations show no "Avg aircraft/day" KPI — a debrief row can carry several services, so summing the flags would not be a plane count.
- **`DFW CABIN` and `DAL PRIV` are separate pages** (Sam, 2026-10-20), undoing the Aug-2026 pooling. The pooled `DFW-DAL` sheet became two sheets; `DAL PRIV` took the five JSX services, `DFW CABIN` kept Envoy/Ultra/Frontier/Regional. **The Ultra and Shroud pins moved to `DFW CABIN` and must stay**: the catalog's `ultras`/`shroudcleaning` templates filter Location ONLY, and `Ultra_Debriefs` holds both job types, so without the explicit `Service` filter every shroud job is counted as an Ultra too. The live build proved it while the override was briefly orphaned — DFW's September budget read 3,416 h instead of 3,245 h and October 2,820 h instead of 2,440 h. The JSX pins were NOT carried over because they are now redundant: the sheet name starts "DAL", so the catalog's `{LOC}` resolves to DAL on its own. **`DAL PRIV` reads budget against zero labor from August onward** — its only person, an Operations Manager, was terminated 2026-07-06 and nobody has been assigned since, while the DFW crew keeps doing the DAL work. That is a knowingly one-sided page, like `SCF PRIV`; the fix is a Paylocity assignment, not a build change. The old `DFW` entry was removed from stations.json so the build stops logging "dropped from the pulse"; nothing referenced it, since DFW-DAL resolves its Envoy/Frontier/Regional services from `service_catalog.json` templates. Re-running `extract_config.py` against the legacy Excel pulse workbook would re-add it — drop it again if so.
- **`DFW WIDE` is the widebody crew, split out of `DFW-DAL`** (Sam, 2026-09-28, the day after widebody was first pooled in). Its own page so the Widebody Turns budget is scored against the widebody crew's own hours instead of being diluted in the DFW-DAL pool: labor dist `DFW WIDEBODY` (17 hourly techs + 1 salaried SOM, all moved off DFW-DAL), `plain_day_dists` carried over, and the catalog's `widebodyturns` template resolves `{LOC}` to DFW from the sheet name. **The page is titled by `display` in `station_overrides.json`** — the Service Budgets sheet is `DFW WIDEBODY` (matching the labor dist) and the tab reads `DFW WIDE`. That is the only display rename in the build; it happens once, where `merged` is keyed, so gates, manager grouping and the month payload all speak one name. Note the trap it fixes: a new Service Budgets sheet with no override gets a labor dist BY CONVENTION (`<code> CABIN`), so before the override this sheet silently published a page showing DFW-DAL's cabin hours under a widebody budget. **A new sheet always needs its `labor_keys` set explicitly unless the convention is genuinely right.**
- **DFW WIDE counts no labor before its first debrief** (`hours_from_first_debrief`, Sam 2026-09-28) — same gate as the JSX stations and BNA AA. `Widebody Debriefs.xlsx` is still empty, and the alternative was a page showing ~700 real hours against a 0 budget, i.e. a crew that looks infinitely over. With the gate the page reads 0/0 and the build says so loudly (`!! DFW WIDE: no debriefs at all — all labor suppressed`); the day the first turn lands, that day and everything after start counting, derived from the data rather than a hardcoded date.
- **Pre-launch labor can be gated per labor dist, not just per station.** A pooled station uses `labor_from_first_debrief: {"<LABOR DIST>": [<service keys>]}` — the named cost centre counts nothing before the first debrief of those services, while the station's other cost centres are untouched. DFW-DAL used it to gate `DAL PRIV` on the JSX services, because the station-wide `hours_from_first_debrief` would have erased ~11,900 h of real DFW history while no gate at all would have scored ~377 h of DAL's imputed-salary time against DFW. **The mechanism is now unused** — the 2026-10-20 split gave DAL PRIV its own page and the ordinary station gate (first JSX debrief 2026-08-19) — but it is kept for the next pooled page, and the reasoning above is why a pooled page cannot just take the station-wide flag.
- **`CLE DAY` / `CLE NIGHT` split one labor dist by shift** (Aug 2026). Both draw on the single `CLE AA` cost centre; `shift_window` in `station_overrides.json` assigns each punch by its local punch-in hour — DAY takes 07:00-18:59, NIGHT takes 19:00-06:59. NIGHT additionally carries **all** CLE AA salaried imputation (DAY has an explicit empty `salary_keys`, which the build now distinguishes from an absent one). Day attribution follows the window: a wrapping (overnight) window keeps the punch-in-minus-12h rule that groups a night shift onto the day it started, while a daytime window uses the plain calendar day — otherwise every 7 AM start would be credited to the previous day. Consequence: totals are conserved but a few hours move between days versus the old combined CLE AA, and May gains ~4 h that previously shifted back past `WINDOW_START`. Ultra, Shroud and Frontier work all belongs to NIGHT; the facility budget is split on the sheets (3.75 + 8 = the former 11.75). Punches with no punch-in time would fall outside both windows — there are none today, and the holiday rows that lack one are already excluded upstream.
- **Pre-launch labor is suppressed.** Stations flagged `hours_from_first_debrief` in `station_overrides.json` (the four JSX sheets and BNA AA) count no labor — hourly, open-shift estimates, or salaried imputation — before the date of their own first debrief. Those hours are implementation and training for a contract that hadn't started, and mostly showed up as pure salaried imputation (5.71 h/day) against a station doing no billable work. The cutoff is **derived from the debrief data each build** (`first_debrief_dates`), not hardcoded, so it moves automatically as debriefs land or are backfilled — and the build logs each station's date. Note this interacts with `JSX_START`: JSX debriefs before 8/1 are dropped first, so a JSX station's cutoff is necessarily its first August debrief.
- **A promotion is not back-applied.** Paylocity flips `Pay Type Code` to `Salary` the day a promotion is entered, but payroll keeps paying hourly until the next pay period. Because the build applies today's pay type to every month it draws, that silently did two wrong things at once to the person's station: dropped every punch they were still working (only `Hourly` punches count) and added 40/7 h a day of imputed salaried time. `Definitive Lists/Pay Type Changes.csv` (maintained daily by the core roster job, `pay_type_changes.py`; rows hand-editable) gives each such person a `salary_from` date — the mirror image of `last_day`. Before it their punches count as hourly and they impute nothing; from it they are salaried. Rows stay on the list **after** their effective date, because removing one would revert every earlier month the day the promotion lands. Found on Riley Pinterich / LIT (Sam, 2026-09-23): LIT was carrying a phantom second salaried head all month while her real hours went uncounted.
- **`FLL` is one page for four customers, with collapsible groups** (Sam, 2026-10-07), replacing the facility-only `FLL FAC` page. A station whose services carry a `group` renders one row per group showing the BUDGET HOURS that group earns; clicking it reveals the member services, which stay what service rows have always been — counts of aircraft serviced. `group_order` in `station_overrides.json` sets the order; a station without groups renders flat exactly as before, so nothing else moved. The four groups: **JetBlue** (APU Wash debriefs, FLL priced identically to JFK and MCO), **NetJets** (its own workbook, the bulk of FLL's revenue), **JSX** (the FLL JSX Private work scope spans four airports — FLL, FXE, OPF, PBI — so each service counts all four, the same shape TEB-HPN uses for two), and **Embraer Facilities** (the janitorial budget the old page carried). Labor is now `FLL FAC` + `FLL PRIV` together (7 + 13 active): the old page scored 7 janitorial staff against a janitorial budget, this one scores all 20 against all four customers. **Both dists take plain calendar-day attribution** (`plain_day_dists`, Sam 2026-10-07) — FLL's crews work daytime, and the non-facility default would shift a morning punch back onto the previous day. Verified against the raw punches: the published hours match the plain-day totals exactly and differ from the shift-back ones on every day. The rates card collapses a group whose services are all priced the same way into one line ("All NetJets labor — $45 of revenue / hour") rather than repeating ten identical rows.
- **A budget can come from a service's own revenue, not an hours rate.** NetJets prices every service PER AIRFRAME — a Complete Exterior is $331 on an EMB-505S and $1,071 on a GL7500 — so there is no single hours-per-job figure to put in Service Budgets. `hours_from` on a service splits what a row SHOWS from what it EARNS: the row still counts aircraft serviced, while its budget is the money beside that count divided by `rate`, read as DOLLARS PER BUDGETED HOUR ($45, Sam 2026-10-07). `load_netjets()` prices each flagged service from the workbook's own Pricing Sheet into a `"<col> $"` column; "Other" takes the debrief's `Other Price`. **Verified on load every build**: those per-service prices are summed and compared against the workbook's own `Job Revenue`, and the difference is printed (currently $0.00 across 102 jobs), so a pricing-sheet change that the flow has not applied shows up as a number rather than a silent drift. The rates card shows these as "$45 of revenue / hour" — "45.00 h / aircraft" would be nonsense.
- **`LCQ FAC` is budgeted from fixed revenue at the facility goal rate** (Sam, 2026-10-10). LCQ bills a static $44,125/month, and the house facility rate is **$30 of revenue per worked hour** — so $44,125 / 30 days / $30 = **49.03 h/day**, flat, every calendar day (the /30 is calendar days, not working days, so this is NOT a `dow_days` budget). The rate is not written down anywhere as a constant; it was derived from the two facility locations that carry fixed monthly revenue in `ERP/Fixed Monthly Revenue.xlsx` — FLL Embraer Facilities implies $29.98/h (248.5 weekly budget hours vs $31,925/mo) and MLB implies $31.09/h. **If the real rate is not $30, one cell on the LCQ FAC sheet fixes it** — the budget is a plain Facility Budget row. No override was needed: the sheet name contains "FAC", so the labor dist resolves to `LCQ FAC` by convention and plain calendar-day attribution follows from being facility-only.
- **Every location is named after the labor distribution it counts** (Sam, 2026-10-10/11). The exceptions are the three pages that genuinely pool dists — `BUR-SNA`, `FLL`, `TEB-HPN` — and `CLE DAY`/`CLE NIGHT`, which split one dist by shift. (`DFW-DAL` was a fourth until the 2026-10-20 split.) 19 commercial sheets were renamed (`BDL`→`BDL CABIN`, `BNA AA`→**`BNA CABIN`**, `SCF`→`SCF PRIV`, `TYS`→`TYS PSA`, `STL AA FAC`→`STL FAC`, `STL GoJet`→`STL GOJET`, …), `IAH` split into `IAH CABIN` + `IAH FAC`, and `STL AA Ultra` split out of `STL AA CAB` with the Ultra and Shroud Cleaning services. Sheets are kept alphabetical, which is the order the page's dropdown uses. `DFW WIDE` became `DFW WIDEBODY` and its `display` override was retired. **Company budget totals are unchanged by the migration; worked hours ROSE** — the STL Ultra crew's ~550 h/month were previously counted nowhere while their budget sat on STL AA CAB.
- **Private/MRO locations are stations too** (Sam, 2026-10-11). `_mro_configs()` reads `Private and MRO Pulse Locations.xlsx`, `load_mro_jobs()` explodes each scheduled job into one row per working day of a synthetic `MRO_Jobs` table (date / Location / Service / Rate / Revenue / Custom), and `mro_stations()` turns each location into an ordinary station: COUNTIFS gives jobs in progress that day and `hours_from` divides the money beside it by the job's revenue rate. So weeks, KPIs, variance and the overview all work untouched, and the page lists all 44 locations. **PARITY MATTERS**: the job→hours rule now exists three times (here, `engine/mro.py`'s `job_hours`, and `mro.js`'s client-side rate) and they must agree — verified against the platform engine on every location before shipping. Two traps found doing it: `spec_mask` compares case-insensitively, so one row per distinct spelling made `PAXX DOOR` and `PAXX Door` each match the other's jobs and double-count (names are now grouped case-insensitively); and a service name can carry two rates (PVU's `XZILON APPLICATION` is premium on booked jobs, base on custom ones), so rows are keyed on rate as well as name.
- **MRO service rows are grouped** via `mro_groups.json` — `_universal` rules (Custom & Extra Labor, Gear Wells, Seat Detailing) plus per-location groups, matched case-insensitively, anything unmatched left as its own row. MCN EMB goes from 59 service rows to 8. Each Private/MRO page carries an **"✎ Edit the forecast"** link to `#labor/mro/<location>` on the platform (`target="_top"` so it escapes the iframe), because the page is read-only and its numbers come from a forecast you otherwise could not reach.
- **Manager grouping still matches on the first 3 letters of the sheet name**, so `BUR-SNA` inherits BUR's managers only (SNA's differ) and `TEB-HPN` inherits TEB's (same as HPN's, so no difference there).
- **Fixed budgets can run on set weekdays.** A fixed service may carry `dow_days` (the weekdays the workbook rate applies to; all other days 0) and optionally `dow_overrides` (per-day hours replacing the rate on named days) in `station_overrides.json`. Both weekday-based items use this one mechanism: **FLL FAC** runs 49.3 h Mon-Fri with a 2 h Saturday half-shift and no Sunday (weekly total 248.5), and **STL AA CAB's Mail Running** is 8 h Mon-Fri with nothing at weekends. The workbook rate means "hours on a normal working day", so editing Service Budgets.xlsx still moves the budget. Note month totals for these services depend on how many working days the month holds, so they will not equal rate x days.
- **Ultra Debriefs holds two job types in one table** (`Service` = "Ultra Cleaning" or "Shroud Cleaning"). The workbook's Ultra COUNTIFS filtered on Location only, so every shroud job was also counted as an Ultra — inflating STL AA CAB by 9 jobs across the window (Aug 2026 fix). All Ultra/Shroud specs now filter `Service` explicitly, in `station_overrides.json` so an `extract_config.py` regen can't revert it. Only STL has shroud rows today; the CMH and DFW entries are latent protection.
- `catalog_extras.json` holds hand-added service templates (AA Turn/RON/Security, Ultra, APU Wash) merged over the generated catalog — regenerating `service_catalog.json` won't lose them. `station_overrides.json` holds per-station exceptions: STL AA CAB / PVD AA CAB labor dist codes match their sheet names (not the `<CODE> CABIN` convention), and STL AA CAB's "Shroud Cleaning" counts from AA_Debriefs, not the Ultra workbook DFW uses.
- The build intentionally **fixes four workbook bugs**: CMH counting LIT's Envoy aircraft (days 2–31), IAH budget rates shifted one row, BDL week-4 hardcoded rates, FLL/TUS FAC days 29–31 pulling MLB FAC's worked hours. Expect those cells to differ from Excel until the workbook is fixed.
- **Data window starts 2026-04-01** (`WINDOW_START`), which is as far back as the punches reach (Sam, 2026-10-20). Paylocity's `This Years Hours.csv` is a CALENDAR-YEAR file and detailed punches in it begin **2026-03-27** — January and February hold only holiday rows (punch-in, no punch-out, 8 h), which the build excludes anyway, and March has five real days. April is therefore the earliest COMPLETE month and the floor for honest history; March would be five days of labor against a whole month of budget. There is no prior-year hours file, so 2026 is the whole of it. The old 2026-05-01 cutoff was inherited from the Excel workbook's M queries and was never a data limit. Debriefs are NOT the constraint — Envoy and PSA reach back to 2024.
- **A gated station is not scored at all before its launch date** (Sam, 2026-10-20). `hours_from_first_debrief` used to suppress only LABOR, which was right while every gated station's budget came from the same absent debriefs. It is not right for a station carrying a flat line: gating labor alone strands the fixed budget against zero hours and reads 100% UNDER — the same error, sign flipped. Both halves now go. A station with no debriefs of its own to derive a date from takes `scored_from: "YYYY-MM-DD"` instead (LCQ FAC, which is fixed monthly revenue and facility-only).
- **Private/MRO locations are gated to their first scheduled job.** The forecast board is a FORWARD-LOOKING planning tool — nobody backfills it — so a month before a location's board was being kept has no budget at all while the crew's real hours are already in Paylocity. Unfixed, the MRO vertical read **+600% over in May 2026** and dragged every company total that included it; the gate takes it to within ±32%, and the company months land at +3/+5/+6/+9/+4/+2/−13%. `mro_stations()` sets `hours_from_first_debrief` and the date resolves against `MRO_Jobs`, so it corrects itself if a board is backfilled. **This was wrong on the published page before the April extension — it is not a side effect of it.**
- Stations whose own feed starts mid-window carry the same gate: `BDL CABIN` (Breeze debriefs begin 2026-06-15; before that the page scored one salaried head against a facility line and read 138% over) and `FLL` (nothing before 2026-05-02). `OMA FAC` and `LCQ FAC` instead mark when their CREW arrived — a budget that released against an empty dist.
- **`SCF PRIV` is left visibly one-sided on purpose**: it carries budget with no worked hours because its Paylocity dist still does not exist. Hiding it would hide a gap that should be closed in Paylocity.
- **Year > quarter > month**, one row of chips above the page (Sam, 2026-10-20). Picking a quarter or a year sums `mtd` across its months — `mtd` is the whole month for a month that has ended and month-to-date for the live one, so a span running up to today is correct without special-casing. The period is deliberately **never persisted**: the page always opens on the current month, so a shared link or a reopened tab shows today's position rather than wherever someone last clicked (the STATION is still remembered, as before). A multi-month period replaces the day grid — which is a month's shape — with a month-by-month breakdown and drops the rates card, whose per-job rates are a point-in-time config and cannot be summed over a span.
- **Master page** ("All Locations — Overview", the default landing view): company-wide MTD KPIs, a per-station table, and By Regional Manager groups. Manager mapping comes from `Power BI Data Sources/Location Management.csv`, matched **blindly on the first 3 letters** of the location on both sides (the airport code) — per the owner's instruction. A location with multiple managers in the CSV appears under each of them, so manager totals overlap and do not sum to the company total.

## Private/MRO hours feed (mro_hours.json)

`build_mro_hours.py` (runs in the same refresh, after `build_pulse.py`) publishes
`mro_hours.json` beside `pulse_data.json`: per-day worked hours for each Private/MRO
pulse location, consumed by the Foxtrot Platform's Private/MRO Labor calendar (see
`MRO_PULSE_PLAN.md` in the foxtrot-platform repo).

- Locations come from `Pulse Sheets/Private and MRO Pulse Locations.xlsx` — one sheet
  per location; columns A/B are a key/value block read until the first blank key. This
  build uses `Labor Distribution` (comma-split for multi-dist) and the optional
  `Attribution` knob; the price matrix from column E is the platform's concern.
- Worked hours call the **same `worked_hours()` the commercial build uses**
  (extracted from `build_month` 2026-08-31; the calculation contract — paid-duration
  punches, holiday/PTO exclusion, dist repair, open-shift estimation, 40/7 salaried
  imputation — lives in that one function). One deliberate difference: **day
  attribution defaults to the plain calendar day** (owner decision 2026-08-31 — MRO
  crews work day shifts; no 12 h shift-back). A sheet can opt back in with an
  `Attribution` row valued `shift`. No launch gating — MRO locations have no debriefs.
- **A labor dist may feed exactly one pulse**: the build hard-fails if an MRO sheet
  claims a dist the commercial config already counts (`BUR PRIV`/`DAL PRIV` are the
  live hazard — both belong to commercial stations today). In the workflow this build
  is `continue-on-error` so an MRO failure can't stale the commercial page; a final
  step still turns the run red.
- Window: last 70 days through today.

## Adding a source

`sources.py` is the **single list** of Data Hub files, shared by `fetch_sources.py`
(downloads them in CI) and `build_pulse.py` (`check_sources_present` fails fast by
name if one is absent). Wire any new source in there — adding a reader to the build
without adding the path here is what broke every scheduled refresh on 2026-08-21.

**`SOURCE_FOLDERS` mirrors whole folders**, for inputs whose contents change as
locations are added and which a fixed file list would silently outgrow. Today that
is `Pulse Sheets/MRO Schedules` — one forecast document per Private/MRO location,
and where those locations' BUDGETS come from. `fetch_sources.py` lists each folder's
children, downloads them into a matching subdirectory, and records each file's
`lastModifiedDateTime`, and **`check_sources.py` polls those children too**, so
editing a forecast triggers a rebuild on its own. The poll half was missing until
2026-10-23: the probe iterated `SOURCE_FILES` only, so a board edit changed nothing
until some OTHER source moved — usually the next morning's Paylocity file. Sam
caught it on AFW EMB, whose six retroactively entered October job-days sat
unpublished for a day while four scheduled polls reported "no change". An added or
removed child counts as a change too, which is how a new Private/MRO location
first appears.
`check_sources_present` fails when a mirrored folder is **absent or empty** — a
missing file already failed loudly, but an empty folder was worse: the build
succeeded and published all eight Private/MRO locations at a 0 budget against real
worked hours (shipped that way for one refresh on 2026-10-10 — the same
"infinitely over" reading the DFW WIDE gate exists to prevent). **Local builds read
the synced Data Hub and so never reproduce this; only CI does.**

## Local development

**The synced Data Hub folder runs BEHIND SharePoint, and CI reads SharePoint.**
Never write a Data Hub workbook from a locally-built copy without first
checking what the live build actually sees. On 2026-10-19 the local copy of
`Service Budgets.xlsx` was one sheet stale — Sam had added `IAD CABIN`
remotely — and installing a locally-rebuilt workbook over it would have
deleted that sheet on the next sync. The tell was the refresh log: CI read
**37** location sheets where the local copy had 36. The published
`pulse_data.json` is the cheap census — its station list is every sheet the
remote workbook holds, and (since the attribution change) it carries each
one's services, rates and labor dists too, which is enough to rebuild a lost
sheet exactly. Check it before and after any write, and keep the backup.

`python build_pulse.py` with no env vars reads the synced Data Hub folder directly. `PULSE_DATA_DIR=sources python build_pulse.py` after `python fetch_sources.py` mimics CI. Open `index.html` — no server needed.
